# Explainer Engine

A natural-language question in, a narrated animated explainer video out.

This is conceptual animation, not data visualisation. It explains mechanisms —
how a hash map works, why compound interest accelerates — and it has no charting
capability at all, on purpose.

## The one architectural idea

**The model never writes rendering code.** It chooses from a fixed library of
twelve hand-built animation archetypes and fills in typed parameters. Everything
that draws pixels is deterministic and hand-written.

That single constraint buys three things: no remote code execution surface, no
unbounded failure modes at render time, and a quality floor set by the archetype
library rather than by whatever the model improvised today.

## Pipeline

```
question
   ├─ gate         Haiku       is this even visualizable?
   ├─ plan         Opus        reason about the concept, in prose, no JSON
   ├─ emit         Opus        forced tool use -> VideoSpec, validated, repaired
   ├─ narration    Kokoro      one wav per beat  (IndexTTS-2 for finals)
   ├─ align        WhisperX    word-level timeline, the authority on timing
   ├─ manim        Python      one transparent WebM per beat
   ├─ compositor   Remotion    titles, captions, transitions, audio -> MP4
   └─ critique     Sonnet      reads keyframes, revises the spec, max 3 loops
```

Plan and emit are separate calls deliberately: forcing structured output in the
same call measurably degrades reasoning, and the reasoning decides whether the
video is any good.

## Layout

| Package | Language | What it owns |
|---|---|---|
| `packages/spec` | TypeScript | The contract. Zod schemas, validation, hashing, JSON Schema export |
| `packages/planner` | TypeScript | The four Claude calls and the spec-repair loop |
| `packages/manim-scenes` | Python | Theme, base class, the twelve archetypes, beat renderer |
| `packages/narration` | Python | Kokoro / IndexTTS-2 adapters, WhisperX alignment, timeline |
| `packages/compositor` | TypeScript | Remotion project, captions, keyframe extraction |
| `packages/api` | TypeScript | Fastify endpoints, BullMQ worker, Postgres, S3 |
| `fixtures/` | JSON | Seven hand-written specs covering all twelve archetypes |

`packages/spec` is the only thing every other package depends on. The Python side
reads the same contract via `packages/spec/schemas/*.json`, regenerated by
`npm run emit-json-schema --workspace @explainer/spec`.

## Quickstart

```bash
npm install
npm run build --workspaces
node scripts/validate-fixtures.mjs
```

Render a hand-written spec without any models installed:

```bash
node scripts/render.mjs --spec fixtures/hashmap.json --dry-run --skip manim,compositor
```

Once the ML stack is installed (see `SETUP.md`), the full offline pipeline:

```bash
node scripts/render.mjs --spec fixtures/hashmap.json
```

And from a question, which needs `ANTHROPIC_API_KEY`:

```bash
node scripts/render.mjs --question "How does a hash map work?"
```

The service version of the same pipeline is `packages/api` — see `infra/README.md`.

## Tests

```bash
npm test --workspaces          # spec, planner, compositor
python -m pytest packages/narration/tests packages/manim-scenes/tests -q
```

No test requires an API key, a GPU, or a model download.

## The three rules

Every archetype enforces these in the base class, not in a prompt:

1. One new element enters at a time.
2. Every reveal is followed by a hold of at least 1.5 seconds.
3. What is no longer relevant is faded out before the next thing arrives.

Plus a hard ceiling of five visible elements, asserted at render time. The
param schemas are sized so a valid spec cannot exceed it.

## What this deliberately does not do

Free-form code generation, multi-language narration, interactive video,
real-time rendering, a web editor, or more than three palettes. Quality first;
a slow pipeline producing excellent video beats a fast one producing generic
video.
